## 这一版解决什么问题

前两版的实测结果：

| 版本 | SPI | 结果 |
|---|---|---|
| v1 | 7.5 MHz | DRDY 修复成功（可用通道 fresh=0.5），但 SPI1 侧通道初始化失败 |
| v2 | 3.75 MHz | 待测；但 G2 上实测**`init_error` 仍存在**，失败仍集中在 SPI1 侧 |

**判断：单纯降 SPI 速率可能不是根本原因。**

### 新的推断

你的板载 EEPROM 里被早期固件烧入了 **`0xA5 = 0x88`**（模拟输出模式）。

```
上电 → EEPROM 自动加载 → 0xA5 = 0x88
     → 固件写 0xA5 = 0x08 想切到命令模式
        ├─ 写成功 → DRDY 正常 → fresh ≈ 0.5        ✓
        └─ 写失败 → 芯片停在模拟输出模式
                    → datasheet 6.3 节：
                      "no matter what 'CMD' registers contents"
                    → 我们写的 0x30 触发命令【被芯片忽略】
                    → DRDY 永不置位 → fresh = 0 永远 ✗
```

**这一个原因同时解释了「初始化校验失败」和「fresh 恒 0」两个现象** —— 因为它们同源。

## v3 的改动

### 1. 运行中自愈（核心）

不再只在上电时写一次配置。现在：

```
某通道连续 4 帧 DRDY = 0
    ↓
自动重写整套配置（0x84→A4/A5/A6/A7）
    ↓
回读 0xA5 存进诊断量
    ↓
重新触发转换
```

每帧最多恢复 8 个通道，避免挤占 1750 µs 扫描预算。

### 2. 不再永久禁用通道

之前初始化校验失败 = 该通道**永久跳过**。现在即使校验失败也照常轮询，靠自愈逻辑救回来。

**实测确认能出数后，会自动撤销 `init_error` 标记。**

### 3. 上电时给失败通道第二次机会

校验失败的通道，初始化末尾会**完整重写一遍配置再回读**（上电瞬间 SPI 状态未稳，一次失败不代表芯片坏）。

### 4. SPI 保持 3.75 MHz

1.875 MHz 不够用（每帧 416 字节需 1.78 ms > 1750 µs 预算）；3.75 MHz 只需 0.89 ms。

### 5. 新增诊断量（Keil Watch `g_tactile_diag`）

| 字段 | 含义 |
|---|---|
| **`recover_attempts`** | 累计自愈次数 |
| **`recovered_mask`** | **曾经自愈成功的通道位图** ← 最有价值 |
| **`stuck_mask`** | 最近一帧仍无 fresh 的通道位图 |
| **`a5_rb_latest[ch]`** | **自愈时重读的 0xA5 值** ← 定位根因的关键 |
| `init_fail_mask` | 初始化失败的通道位图 |
| `init_a5_rb[]` / `init_a6_rb[]` / `init_a7_rb[]` | 各通道回读值 |
| `prime_conversion_us` | 真实转换时间 |

**`a5_rb_latest[]` 的判读**：

| 读到 | 含义 |
|---|---|
| `0x08` | 写入生效 → 问题在别处（不是模式问题） |
| `0x88` | **写入没生效，芯片仍在模拟输出模式** ← 确认根因 |
| `0x00` | SPI 事务失败 → 通信问题 |

## 烧录后怎么判断

### 用上位机看（不需要调试器）

```bash
cd ~/tactile && .venv/bin/tactile500 probe --seconds 10
```

| 观察 | 含义 |
|---|---|
| `per_channel_fresh_fraction` 全部 ≈ 0.5 | ✅ **成功**，全部通道自愈 |
| 只有部分通道 ≈ 0.5 | 自愈救了部分，其余需查 `a5_rb_latest[]` |
| 仍有个别通道 0.0 | 那几块芯片可能有硬件问题 |
| `status` 里 `init_error` 消失 | ✅ 全部通道恢复正常 |

### 用 Keil 调试器看（定位根因）

Watch 窗口加 `g_tactile_diag`，重点看：

1. **`a5_rb_latest[]`** —— 自愈后 0xA5 读回什么？
   - 全是 `0x08` → 模式正常，问题在 SPI 时序
   - 出现 `0x88` → **确认是模式锁定问题**
2. **`recovered_mask`** —— 哪些通道被救回来了
3. **`prime_conversion_us`** —— 真实转换时间（预期 2000~4000 µs）

## 如果 v3 还是不行

那说明问题不在「0xA5 写入」这条路径上。下一步可以考虑：

1. **检查 SPI1 硬件** —— PA5/PA6/PA7 的走线、上拉、总线电容
2. **降低 SPI 到 1.875 MHz 并放宽扫描预算** —— 需要同时调整 `TACTILE_SWEEP_BUDGET_US`
3. **对比测试单块板** —— 只接一块板时是否正常（排除总线负载）
