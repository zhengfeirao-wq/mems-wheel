# 固件修订 0x21：首次实机反馈后的修正

初版实机结果为 V2 0x20、约125帧/秒、序号每次跳4、TX_BUSY锁存和全部启动哨兵。
这说明编译通过没有代替实物验收。

1. APM32F402普通DMA计数归零后CHEN仍保持置位，所附DAL没有在下次重装计数前关通道。
   现于USART2的UART TC完成回调关闭DMA通道，确认末尾停止位发完后再释放缓冲区。
   这样下一帧可重装计数，不再等待超时恢复，也不提前截断尾部。
2. 配置NSA2302时先A5=08关闭DAC模式，设置A6/A7后最后A5=88启动。对接口和A5/A6/A7
   精确读回校验；保留原OSR/滤波和EEPROM标定，不重新烧写EEPROM。
3. DRDY=0时仍读取寄存器，避免一直输出启动哨兵；仅DRDY=1且读取成功时设置fresh位。
4. 版本字节改为0x21，六个GNU目标重建；用户通过Keil重建并烧录了左12和左32短线。

重新插回G1后收到身份08/0E、修订21。交换Hub口不影响按协议识别角色。两板恢复到约500
帧/秒，温度/压力有可读值，未出现SPI/初始化/TX错误位。同步PyUSB读取仍出现少量丢字节；
上位机用PyUSB的libusb1后端预排队异步请求后，30秒短测两板均没有序号缺口。
后续持续测试见相邻gpt6上位机项目的reports与验收报告。

当前DAC模式DRDY实测全0，不能据此宣称每通道500Hz新ADC转换。尚无示波器边沿、ADC
带宽/噪声测量，固件仍为TX连续输出，未增加共享触发或接收同步启动命令。
