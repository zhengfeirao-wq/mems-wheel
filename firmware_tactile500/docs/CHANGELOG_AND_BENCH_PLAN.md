## 主要修正

| 项目 | 原代码 | 当前实现 |
|---|---|---|
| 名称/入口 | I2C/I2C_TwoBoardsPolling，与实际双 SPI 触觉用途不符 | Applications/Tactile500；六种具名 Target |
| 主频/总线 | 按 16 MHz 晶振，HSE×8=128 MHz，APB1 也为 128 MHz | HSE/2×15=120 MHz；APB1=60 MHz，APB2=120 MHz |
| 帧周期 | 主循环尽快发，节拍接近串口吞吐极限 | TMR2 每 2000 us 触发发送已准备好的帧 |
| USART2 DMA | CIRCULAR，在完成回调中 DMAStop | NORMAL；DMA 完成后由 UART TC 确认真正发完，再释放缓冲 |
| 帧缓冲 | 一块全局缓冲，状态处理脆弱 | 两块独立缓冲，FREE→BUILDING→READY→SENDING→FREE |
| 启动失败 | DAL_UART_Transmit_DMA 返回值检查后有空分号 | 检查 DAL 状态及 DMA CHEN，失败记录并请求恢复 |
| 回调 | 缺少 USART2 明确隔离 | 只处理 USART2；正常完成不执行 DMAStop |
| SPI 读取 | 单字节 val 作为多字节发送指针，越界读；超时可达 100/1000 ms | 长度正确的 7 字节缓冲；单事务 100 us，单轮采集预算 1750 us |
| MISO | 复用推挽输出 | 主机 MISO 配置为输入 |
| 温度 | 未先将原始 16 位数符号扩展 | 先按 int16 解释再缩放，支持负温度 |
| 传感器有效性 | 连续读数不核对新数据 | 读取 DRDY/ERROR_CODE，fresh_mask 标记；异常保留缓存 |
| 上电标定 | 写统一系数并触发 EEPROM 编程 | 不再覆盖 0xAA 等校准系数，不触发 0x6A/0x6C 烧写 |
| 识别/诊断 | 地址和通道数，缺少长短线标识 | 六板型身份、映射版本、序号、时间、fresh、status、CRC |

主频和 APB1 调整依据：[Geehy APM32F402xB User Manual V1.1，第 31–32 页](https://global.geehy.com/uploads/tool/APM32F402xB%C2%A0User%C2%A0Manual%C2%A0V1.1.pdf)。按厂商限制，AHB/APB2 最大 120 MHz，APB1 最大 60 MHz。晶振仍按原硬件参数 16 MHz 配置，上板必须确认实际晶振。

旧单缓冲设计并不自动证明存在 DMA 改写竞争；本次修正的是已经看到的循环模式、返回值处理及指针越界等问题，不将旧数据异常归因写成实测结论。

| SPI1 | PA5/PA6/PA7=SCK/MISO/MOSI，120 MHz/64=1.875 MHz |

| SPI 模式 | Mode 0，8 bit，MSB first，软件片选；MISO 输入 |

## 为什么用两个缓冲区

主循环只写 FREE 缓冲区，读完传感器并算完 CRC 后标为 READY。TMR2 中断只选择本时隙 READY 帧启动 DMA；另一个缓冲区可以同时准备下一帧。DMA 使用的 SENDING 缓冲区在 UART TC 前不改写。

传输尚未结束时不会覆盖或叠加发送。定时启动迟到超过 20 us 时跳过该时隙；序号照常增加，下一帧能看到缺口。活动传输跨过约 4 ms 仍未结束时，请求主循环停止异常传输、复位驱动发送状态，再继续后面的周期。异常恢复可能形成残帧；上位机通过 CRC 和同步头恢复。

中断和主循环共享状态只在极短临界区内修改，SPI 采集、CRC 运算和等待均不放在临界区。DMA 半传输中断在每次启动后关闭，以减少无用中断。无帧队列积压，不做“赶进度”突发补发。

## 带宽和采样限制

921600、8N1 每字节占 10 个串口位：

| 规模 | 字节/帧 | 按标称波特率发送时间 | 2 ms 周期内剩余 |
|---|---:|---:|---:|
| 12 点 | 80 | 868.06 us | 1131.94 us |
| 32 点 | 180 | 1953.125 us | 46.875 us |

60 MHz PCLK1 下驱动的整数波特率分频值为 65，实际标称约 923076.9 baud（比请求值高约 0.16%），32 点线占用约 1950 us。实测以逻辑分析仪为准，主机仍设置 921600。

32 点留给中断延迟和下次启动的余量很小。若真实 UART 波形存在超期，先查时钟、SPI 用时、中断和硬件链路；不要在上位机通过丢包/插值掩盖。协议已经接近当前波特率能容纳的大小，新增字段前必须重新核算。

本轮没有调整 NSA2302 模拟采样滤波，不能把 500 Hz 发包直接等同于每个通道 500 Hz 新测量。如果 fresh 比例不足而链路稳定，应另做 DRDY 周期与 OSR/噪声测试后决定参数；也不能通过把 fresh 位强制置 1 解决。旧固件已写入 EEPROM 的内容不会因这次停止写入而自动恢复，若原始标定已丢失，需要原备份或重新标定。

## 烧录顺序（现场执行）

1. 确认实际板型、主芯片丝印、16 MHz 晶振、供电和烧录器型号；仅连接一块触觉板。左右及长/短线必须与 Target 对应。
2. 安装用户目录中的 MDK527.EXE，再安装 Geehy.APM32F4xx_DFP.1.0.7.pack。或者使用已安装且支持 APM32F402RB 的烧录工具直接下载现成 GNU HEX。无需运行其他未必相关的安装程序。
3. 打开 `Project/MDK/Tactile500.uvprojx`，选择表中正确的 Target，Rebuild。输出 `build/keil/<Target后缀>/Tactile500_<Target后缀>.hex`。如提示 Arm Compiler 缺失，按实际已安装编译器选择；不要忽略错误使用旧 HEX。
4. 在 Debug/Utilities 中按实际探针选择驱动、SWD 接口、低速起步（例如 1 MHz）；查到正确芯片后再下载。工程未固定原作者的探针序列号。SWDIO/SWCLK/GND/参考电压按板子丝印接，不凭颜色猜。
5. Flash 算法应为支持包的 `APM32F402_128.FLM`；Flash 范围从 0x08000000 起共 0x20000 字节。HEX 自带地址；BIN 才需要手动指定起始地址。
6. 使用一种构建产物烧录并执行 Verify。结束调试单步与断点，让 MCU 自由运行；重新上电约 1 s 初始化后开始数据流。记录具体固件文件和 build_manifest.json 哈希。

## 分阶段验收

| 阶段 | 操作 | 通过条件/记录 |
|---|---|---|
| A：只读确认 | 看芯片、晶振、供电、探针识别 | 板型和参数与工程一致，记录照片/型号 |
| B：首次 10–30 秒 | 一块板烧录并核验，逻辑分析仪测 PA2 与 SPI | UART 可按 921600/8N1 解码，帧头间隔约 2 ms；SPI 两路约 1.875 MHz；没有持续初始化/SPI 错误 |
| C：1 分钟协议 | 持续收取 UART 字节并保存，每个设备独立文件 | CRC 合法；长度 80/180；身份与实物一致；sequence 连续且无重复；timestamp 增量约 2000 us |
| D：通道映射 | 无载荷静置，再逐点按压 12 或 32 点 | 位置与通道一一对应，左右正确，长/短线未二次换序；检查负温度/无效值解码 |
| E：30 分钟稳定性 | 一块板连续采集，随后再测多板同时接入 | 期望约 900000 帧/板；稳态窗口 CRC 错误=0、内部缺口=0、重复=0；PC 实时时钟计算帧率并记录偏差 |
| F：新数据率 | 逐通道统计 fresh_mask 比例，并观测 DRDY/采集波形 | 分别报告各通道“收到的帧率”和“有效新数据率”；若不是 500 新测量/s，保留原始证据再调整模拟参数 |
| G：错误恢复 | 稳态通过后再做可控断连/读超时试验 | 不永久卡死，恢复后能重同步；状态/序号能揭示故障；先停电再改接线 |

开始/结束截断的半帧应单独记录，不混入稳态 CRC 错误统计。30 分钟总数需考虑 PC 计时窗口边界和晶振误差；同时要求窗口内 sequence 没有缺口，不能只看约 500 的平均值。主机一次 USB 读取的时间间隔不是 UART 发包间隔。

离线报告命令：

```powershell
python tools/protocol_v2.py capture.bin --output capture_report.json
```

该报告输出有效帧数、错候选头数、丢弃字节、尾部半帧、序号缺口/重复/回绕后的速率、各通道 fresh 比例和 status 计数。它的速率使用 MCU 采集时间，物理 500 Hz 必须另配 PA2 波形或 PC 单调时间记录。每个 USB 设备各存一份，避免同型两板的序号相互混淆。

调试器可只读观察 `g_tactile_stream.sent_frames`、`missed_slots`、`sweep_overruns`、`tx_errors`、`latched_status`。暂停 CPU 会人为破坏时序；看完后重新上电再做正式计数。
