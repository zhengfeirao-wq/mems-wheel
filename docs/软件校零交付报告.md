## 一、需求

系统集成方（采集系统）提出三点要求：

| # | 要求 | 说明 |
|---|---|---|
| 1 | **输出值接近 0** | 未接触时压力读数应在 0 附近，便于判读 |
| 2 | **每次开始采集时校零一次** | 采集系统启动即执行，不需人工干预 |
| 3 | **原始数据保留、可回溯** | 要求能用连续多日（如 5 天）的数据观察零点漂移 |

---

## 二、设计原则

模块围绕三条原则实现，**所有设计取舍均由此推导**：

### 原则 1：原始值永不修改

`frame.pressure` 始终是固件原始值。校零只是**视图变换**，任何时刻都能取回原值：

```python
shown = tared.apply_frame(frame)   # 校零后（0 附近）
raw   = frame.pressure             # 原始值，一直都在
raw2  = TareFilter.raw(frame)      # 同一份数据
back  = restore(shown, offsets)    # 从校零值反算回原始值
```

### 原则 2：每次校零都留档

每次校零追加一行到 `~/.tactile500/tare/journal.jsonl`，记录：

- 时间戳（UTC）
- 每通道偏移值与极差
- 每通道状态
- 板 identity（`0x08` / `0x09` / `0x0A` / `0x0B`）
- 警告清单

**按 identity 索引而非 USB 路径，换 USB 口不失效。** 由此可事后统计零点随时间的漂移。

### 原则 3：坏通道不静默处理

饱和或无数值的通道**给 0 偏移并明确标记**，不给予一个假零点把故障掩盖过去。

---

## 三、关键技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 校零层次 | **上位机软件**（不动固件/芯片） | 零风险、可回退、随时可改；芯片标定系数在 EEPROM，本模块完全不碰 |
| 偏移估计量 | **中位数** | 本系统存在满量程尖峰（如某通道跳至 ±943718），均值会被单个尖峰拉偏数百单位 |
| 稳定性评估样本 | **仅用 `fresh_mask` 命中帧** | 500 Hz 帧率下单次转换约 250 Hz，非 fresh 帧是重复值，用于计算极差会**低估**真实波动 |
| 校零方式 | **一次性**，不做滑动基线 | 滑动基线会把缓慢变化的**真实力**当成漂移减掉，在动态夹爪上很危险 |
| 通道状态 | 四档：`ok` / `unstable` / `saturated` / `no_data` | 使调用方可分别处理，而非笼统成败 |

## 四、接口

### 4.1 命名（统一 `tare` 前缀，搜索即可找齐全套）

| 名称 | 类型 | 作用 |
|---|---|---|
| `tare_now()` | 函数 | **唯一入口**：采一次零点 |
| `TareResult` | 类 | 一次校零的完整结果 |
| `TareFilter` | 类 | 把零点应用到实时帧 |
| `TareJournal` | 类 | 追加式档案 |
| `ChannelBaseline` | 类 | 单通道基线统计 |
| `restore()` | 函数 | 还原成原始值 |

### 4.2 集成方式（三步）

```python
from tactile500 import TactileSystem
from tactile500.tare import tare_now, TareFilter, TareJournal

system = TactileSystem()
native = system.subscribe(capacity=16384)
system.open()

# ① 采集系统启动时：夹爪张开、无接触，采 2 秒基线
result = tare_now(system, seconds=2.0)
for w in result.warnings:
    print("校零警告:", w)

# ② 留档（可回溯、可看长期漂移）
TareJournal().append(result, note="第 1 天开机")

# ③ 之后所有输出取自校零后的值
tared = TareFilter(result)
while True:
    item = native.get(timeout=1.0)
    shown = tared.apply_frame(item.frame)   # 0 附近
    raw   = item.frame.pressure             # 原始值，一直都在
```

### 4.3 主要参数

`tare_now(system, *, seconds=2.0, roles=None, fresh_only=True, min_samples=50, max_spread=20000, reject_saturated=True)`

| 参数 | 默认 | 说明 |
|---|---|---|
| `seconds` | 2.0 | 基线时长，建议 1~3 秒 |
| `roles` | `None` | 只校指定角色；`None` = 全部在线板 |
| `fresh_only` | `True` | 稳定性评估只用 fresh 帧 |
| `min_samples` | 50 | 少于该帧数判为 `no_data` |
| `max_spread` | 20000 | 极差超此值判为 `unstable` |

**该函数自开订阅、采完即关，不影响调用方自身的订阅。**

### 4.4 命令行工具

```bash
python tools/tare_journal.py show                     # 列出全部校零记录
python tools/tare_journal.py drift 0x0A               # 每通道漂移（末次 − 首次）
python tools/tare_journal.py drift 0x0A --channel 1   # 单通道逐次漂移
python tools/tare_journal.py latest 0x0A --out t.json # 导出最新一次
python tools/tare_journal.py restore raw.csv t.json   # CSV 还原为原始值
```

## 五、实机验证

**平台**：AgiBot G2（Ubuntu 22.04 / aarch64 / 5.10.220-rt112 实时内核）
**配置**：四板共 88 通道，各 500 Hz 接收
**版本**：tactile500 0.4.1（安装后复验）

### 5.1 基线采集结果

| 角色 | 通道 | ok | 不稳 | 饱和 | 无数据 |
|---|---:|---:|---:|---:|---:|
| right_palm | 32 | 32 | 0 | 0 | 0 |
| left_palm | 32 | 32 | 0 | 0 | 0 |
| right_fingers | 12 | 12 | 0 | 0 | 0 |
| left_fingers | 12 | 11 | 0 | **1** | 0 |
| **合计** | **88** | **87** | 0 | **1** | 0 |

**唯一异常**：`left_fingers` ch0 顶到满量程（±943718，即 24 位 ADC 到达端点）。
模块**已按设计跳过并告警**，未给予假零点：

```
⚠ left_fingers ch0 顶到满量程，已跳过（硬件/接线问题）
```

该通道为硬件/接线问题，**非软件缺陷**（芯片自身的错误码 `Negative signal out of range` 亦对应此现象）。

### 5.2 校零效果

| 角色 | 校零后前 3 通道 | 校零后绝对值最大 | 满量程 |
|---|---|---:|---:|
| left_palm | 16, 10, 11 | **66** | 943718 |
| right_palm | -20, -3, -34 | **55** | 943718 |
| right_fingers | 210, -141, 90 | **379** | 943718 |
| left_fingers | (-943718 饱和), 194, 5 | 见备注 | 943718 |

**残差为满量程的 0.006% ~ 0.04%**，满足"输出值接近 0"的要求。

> 备注：`left_fingers` ch0 因饱和未校零，读数保持原始饱和值——这是**有意为之**，
> 避免把硬件故障伪装成"已修复"。

### 5.3 可回溯性验证

| 验证项 | 结果 |
|---|---|
| `restore(shown, offsets) == raw` | **四板全部一致** ✓ |
| `frame.pressure` 是否被修改 | **未被修改** ✓ |
| 档案写入 | `~/.tactile500/tare/journal.jsonl` ✓ |

### 5.4 自动化测试

- 校零专项测试：**12 项**（含饱和/不稳/无数据判定、档案与漂移、还原回路、别名兼容）

## 六、已知边界

| # | 边界 | 说明 |
|---|---|---|
| 1 | **单位仍为"固件值"** | 本模块输出**相对变化量**；绝对值量纲（Pa / N）需另行实物标定 |
| 2 | **需人工保证空载** | 校零时夹爪必须张开且无接触；模块仅能通过数值稳定性兜底提示 |
| 3 | **一次性校零** | 不自动跟随温漂；需要时再次调用 `tare_now()` |
| 4 | **不替代芯片标定** | 芯片标定系数存于 NSA2302 的 EEPROM（`0xAE`~`0xBC`），本模块完全不读写 |
| 5 | **饱和通道无法修复** | 硬件问题；模块的职责是**如实报告**而非掩盖 |
